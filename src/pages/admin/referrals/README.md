# 추천 계보·포인트 조회 경계

- `api/referralReads.ts`는 기존 users 명시 필드/탈퇴 제외와 선택 user_id의 point_logs 최신순 조회를 담당한다. 응답 오류·목록/핵심 형식을 검사해 정규화하며 쓰기·지급·이체·알림은 호출하지 않는다.
- 화면은 관리자 포털 역할을 검사한다. 사용자 목록은 **기존처럼 서버가 허용한 전체 결과를 요청**한다. 클라이언트 하위 계보/내 계보 표시는 서버 접근 제어가 아니다. 비관리자의 실제 조회 범위와 개인정보 노출 방지는 별도 RLS 검증이 필요하다. 이 작업에서 서버 정책/조회 권한은 변경하지 않았다.
- 사용자 목록과 포인트 기록은 별도 요청 번호를 사용한다. 계정 변경/이탈·목록 재조회 시 이전 요청과 선택/기록을 무효화한다. 새 사용자 목록이 확인되기 전에는 이전 계정의 users를 트리 계산에 사용하지 않는다.
- 포인트 조회는 현재 목록에 있고 관리자 전체 보기 또는 자기 하위 계보에 속한 선택 사용자만 시작한다. 범위 변경·선택 변경 후 이전 응답/오류/로딩은 반영하지 않는다. 기록에 계정 객체/사용자 ID를 연결해 새 선택이 렌더되는 즉시 이전 기록을 숨긴다.
- 부모는 기존 lineage 마지막 ID 우선, 없으면 referred_by 사용자명 매핑 규칙이다. 부모 판정을 useCallback으로 안정화하고 자식/루트 memo는 그 함수를 의존한다. BFS 방문 집합을 유지하고 재귀 렌더도 현재 경로를 검사해 순환을 반복하지 않는다. 순환 DB 정정이나 모든 잘못된 계보를 복구하는 기능은 아니다.
- 새 목록 조회 후 자기 계정을 선택하고 확장을 자기 노드 기준으로 초기화한다. 조회 실패는 이전 목록/선택/기록을 정상 결과처럼 남기지 않고 공통 오류로 안내한다. 기존 표시 UI와 검색 규칙은 유지했다.
- 서버 행 수 제한/페이지 처리·서버 수준 계보 권한·중복 사용자명·매우 깊거나 큰 트리·포인트 회계 정책·브라우저 검수는 별도다. 전체 금융 원장을 검증한 것이 아니다.
- `npm run test:referrals`: 실제 DB/포인트 변경 없이 읽기 계약·오류·선택/계정 변경·표시 소유자·계보 판정/순환·문구 동기화를 확인한다.
