# 학습·상담일지 유지보수

## 현재 경계

| 파일 | 책임 |
| --- | --- |
| `views/AdminStudyTab.tsx` | 학습일지 입력·선택·확인 창·상태 반영·내보내기 진입 |
| `views/AdminCounselTab.tsx` | 상담일지 입력·선택·확인 창·상태 반영 |
| `api/studyData.ts`, `api/counselData.ts` | 각 화면의 전체 조회 결과 구성 |
| `api/studyWrites.ts` | 학습일지 저장·수정·공개·삭제와 반환 행 확인 |
| `api/counselWrites.ts` | 상담일지 저장·수정·조건부 공개·삭제와 반환 행 확인 |
| `api/journalNotification.ts` | 이미 저장된 학습·상담일지의 기존 Edge 알림 요청 |
| `model/studyExport.ts` | 불러온 전체 일지를 Excel의 9개 출력 필드로 변환 |
| `files/studyWorkbook.ts` | 학습일지 시트·열 너비·틀 고정·줄바꿈과 xlsx 버퍼 생성 |

## 학습일지 쓰기

- 기존 `academy_study_logs` 테이블의 insert/update/delete 경로를 유지한다. 새 RPC·알림 자동 반복·다른 저장 경로로의 우회는 없다.
- 수정 시 기존 학부모 공개 상태를 유지한다. 이미 공개된 일지를 알림 없이 수정해도 비공개로 돌아가지 않는다. 새 내부용 일지에는 알림을 요청하지 않는다.
- 저장 응답의 일지 ID·학생·지점·공개 상태를 검사한다. 공개·삭제는 같은 ID의 반환 행을 확인한다. 응답 미확인은 성공/실패로 단정하지 않고 최신 내역을 먼저 확인하도록 안내한다.
- 공개 성공을 확인한 뒤에만 알림을 요청한다. 알림 실패 시 저장/공개 결과는 유지하고 `JOURNAL_NOTIFICATION_FAILED`로 별도 안내한다. 일지를 다시 작성하거나 자동으로 알림을 반복하지 않는다.
- 알림의 대상·푸시 접수·실패 수는 검증한 숫자만 표시한다. 서버 원문·토큰·이름은 오류 화면/로그에 내보내지 않는다. 전송 접수는 기기 수신 보장이 아니다.
- 저장·공개·삭제는 하나의 동기 잠금을 공유한다. 확인 창 전 중복 요청을 막고 finally에서 해제한다. 지점 변경/조회 갱신 후 오래된 결과가 새 목록을 덮어쓰지 않는다.
- 학생 선택/편집 전환 시 폼 번호가 바뀐다. 이전 저장 응답은 새 학생/편집 폼을 초기화하지 않는다. 같은 폼에서 요청 중 입력을 직접 바꾸는 동작까지 충돌 해결하는 편집 버전 관리는 아직 없다.

## 상담일지 쓰기

- `academy_counsel_logs`의 기존 insert/update/delete 경로와 상담자·상담일·분류·본문 필드를 유지한다. 상담 분류의 표시 이름이나 DB 값을 이번 작업에서 바꾸지 않았다.
- 기존 공개 일지는 알림 없이 수정해도 공개 상태를 유지한다. 저장 응답의 ID·학생·지점·공개 상태를 확인한 뒤에만 목록에 반영하고 알림을 요청한다.
- 공개는 기존 `is_parent_visible = false` 조건을 유지한다. 반영 행이 없으면 기존 `CONFLICT_ERROR`를 안내하고 알림을 보내지 않는다. null 공개값에 대한 처리나 별도 RPC를 추가하지 않았다.
- 삭제도 반환 ID를 검사한다. 반영 행 없음은 기존 충돌 안내, 다른 ID·응답 유실은 결과 미확인으로 구분한다. 상태 조회 없이 같은 작업을 반복하지 않는다.
- 저장·공개·삭제는 동기 잠금을 공유한다. 학생 선택·편집 시작·수정 취소 시 폼 번호를 바꾸므로 이전 저장/삭제 결과가 새 편집 내용을 비우지 않는다. 지점/조회 변경 후 이전 목록 갱신도 차단한다.
- 알림 오류는 이미 저장/공개된 일지에 대한 별도 경고다. 저장된 행을 유지하며 새 일지를 만들거나 자동 재알림하지 않는다. 푸시 실패 수·대상 없음은 별도로 표시한다.
- 학습과 같은 폼에서 요청 중 직접 입력한 새 문자의 충돌 해결, 다중 탭 편집 버전 검사, 서버 저장/알림의 원자성은 아직 별도 과제다.

## 검증과 남은 작업

- `npm run test:journals`: 외부 연결 없는 조회·학습/상담 쓰기·알림·화면 콜백 테스트.
- 실제 RLS의 수정/삭제 반환 행 조회 권한, 공개 후 앱 동기화/알림, 다중 기기 동시 편집은 격리 환경에서 별도 검수해야 한다.
- 저장과 알림은 별도 처리다. 알림 실패 전 서버에 일부 알림/푸시가 저장·전송되었을 수 있으므로 발송 이력 확인 없이 반복하지 않는다.
- `is_parent_visible`이 null인 과거 학습일지도 기존 공개 경로를 유지한다. 서버 조건부 갱신·다중 탭 공개 중복 방지와 원자성은 별도 과제다.
- 학습일지 Excel은 기존처럼 불러온 전체 목록(내부용·과거 반 전체 일지 포함)을 출력한다. 선택 학생/검색 필터만 출력하도록 바꾸지 않았다. 포함된 내용·특이사항은 개인정보일 수 있으므로 다운로드 파일의 보관/전달을 별도로 관리해야 한다.
- `npm run test:excel`로 실제 xlsx 생성 후 다시 열어 열 순서·내용·너비·틀 고정·줄바꿈을 검증한다. 브라우저 다운로드 완료나 실제 Excel 앱의 표시를 보장하는 테스트는 아니다.
- 학생 업로드와 AdminPage 축소는 후속 작업이다. SQL·운영 배포는 이번 범위에 포함하지 않는다.
