# 수업·시간표 기능 경계

- `views/AdminClassTab.tsx`: 수업 관리의 조회·입력·확인·실행 수명 관리 화면. 저장/삭제 서비스는 아래 파일로 분리했다.
- `api/weeklySchedule.ts`: AdminPage의 주간 시간표·예약·학생·보호자 읽기 전용 조회. client를 전달받고 모든 응답의 error/배열 여부를 검사한다.
- `model/weeklySchedule.ts`: 주간 조회 타입, 기존 취소 상태 5종 제외, 지점 조인 정규화와 연결 인물 조립을 담당한다.
- `api/classManagementReads.ts`: 수업 관리의 users 강사·academy_teachers 강사·class_schedules 초기 조회와 타입. 세 조회가 모두 정상일 때만 반환하고, 수업의 강사 조인 object/array를 정규화한다. 요금제/학생 배정은 이 초기 조회 대상이 아니다.

## 수업 관리 초기 조회

- users 역할 집합(teacher/coach/director), 사용자 강사 우선·ID/이름 중복 처리, 지점 필터, 수업 전체 조회 조건은 유지했다. 활성 수업만으로 바꾸거나 탈퇴 강사 필터를 새로 추가하지 않았다. 전체 지점에서 이름만 같은 다른 강사를 제외할 수 있는 기존 정책은 별도 검토 대상이다.
- 정상 응답 전에 강사 목록만 먼저 반영하지 않는다. 실패 시 두 목록을 함께 비우고 공통 오류를 표시한다. UI는 조회 전/실패 상태에서 편집창 열기와 저장 버튼을 막는다.
- AdminPage가 profile을 전달하며 일반 계정은 자기 지점으로 조회한다. 지점 없는 일반 계정/지원하지 않는 역할은 조회 전에 차단한다. 실제 데이터 권한은 서버 RLS가 담당한다.
- loader를 useCallback으로 안정화하고 지점/계정·요청 번호를 확인한다. 범위 변경/화면 이탈은 이전 요청과 편집 상태를 정리한다. 이전 저장 콜백의 재조회가 새 범위를 읽는 것도 막는다.
- 수업 저장/삭제 서비스와 클라이언트 수명 검사는 아래 단위로 보완했다. 기존 학생 배정/청구 영향·실제 서버 권한·동시 편집은 별도 점검이 필요하다.
- `npm run test:class-management`: 실제 DB 변경 없는 세 조회의 오류/비정상 응답·조인·중복 정책·계정/지점 변경·편집 준비 상태·문구 동기화 테스트다. 대량 행/실제 RLS/브라우저 검수는 별도다.

## 수업 저장·삭제

- `model/classWrite.ts`는 제목/지점/강사 UUID/요일/HH:mm/정원을 검사한다. 종료는 시작 이후인 당일 수업을 대상으로 하며 정원은 공란(null) 또는 양의 int32 정수다. 야간 날짜 넘김/0명 정원 정책은 지원하도록 새로 정의하지 않았다.
- `api/classWrites.ts`는 기존 insert/update/delete를 한 번 수행하고 select/single 반환을 검사한다. 수정/삭제는 원래 행 ID와 원래 branch_id(또는 명시적 null)에 함께 조건을 건다. 저장은 요청한 전체 필드, 삭제는 삭제된 ID를 확인한다. SELECT 권한/응답 유실이 있어도 앞선 변경이 적용됐을 수 있다. 자동 재시도·아카이브 전환·다른 테이블 쓰기 우회는 없다.
- 화면은 정상 조회·현재 계정/지점·대상 목록·선택 지점·강사 지점 일치를 확인한다. 사용자 강사 UUID가 academy_teachers 외래키와 맞지 않는 기존 데이터 문제를 임의 생성/매핑으로 우회하지 않는다.
- 저장/삭제는 같은 ref 잠금을 사용한다. 실행 중 입력/닫기/새 편집을 막으며, 기존 조회 응답을 무효화하고 일반 재조회를 막는다. 변경 응답 뒤 명시적 재조회만 허용한다. 응답 미확인은 정상 재조회 전 재실행을 제한한다. 탭을 다시 열거나 페이지를 새로고침해 먼저 실제 상태를 확인한다.
- 변경 응답 확인 뒤 목록 실패는 `CLASS_WRITE_REFRESH_FAILED`로 구분한다. 지점/계정/편집 epoch 변경 후 이전 작업은 새 창을 닫지 않는다. 화면 이탈 뒤 새 조회를 시작하지 않으며 다른 지점으로 이동했다면 잠금 해제 후 최신 loader로 현재 범위를 조회한다.
- **삭제 정책 미확정**: 로컬 과거 스키마에는 `academy_bills`, `academy_student_classes`, `academy_student_monthly_plans` 등의 수업 외래키에 ON DELETE CASCADE가 있다. 운영 DB의 현재 일치 여부는 확인하지 않았다. 기존 하드 삭제를 유지했으므로 반환 ID 확인이 청구 이력 보존을 보장하지 않는다. 운영 반영 전에 연쇄 영향·소프트 삭제/금지/RPC 정책을 사업·DB 책임자가 확인해야 한다. 이번에 실제 삭제나 서버 정책 변경은 하지 않았다.
- 브라우저 다중 기기 동시 수정·서버 권한·외래키 정책·시간 반환 형식·실제 예약/청구 영향은 별도 검수다. 클라이언트 잠금은 멱등성/버전 비교/서버 트랜잭션을 대체하지 않는다.
- `npm run test:class-writes`: 실제 DB 변경 없는 입력/응답·지점/대상 검증·중복 실행·화면 전환·조회 부분 실패·문구 동기화 테스트다.

## 조회 계약

- 활성 시간표, 시작시각 순서, 삭제되지 않은 예약의 7일 범위와 선택 지점 필터를 유지한다. 최고관리자의 전체 지점은 null을 사용하며 지점 없는 일반 계정은 화면에서 차단한다. 실제 권한 보장은 서버 RLS가 담당한다.
- 취소 상태는 `cancelled`, `canceled`, `취소`, `취소요청`, `cancel_requested`를 제외한다. 자녀 ID·보호자 ID는 중복 제거해 조회하고 삭제된 자녀/탈퇴 사용자 조회 제외 조건을 유지한다.
- 연결된 자녀/보호자가 조회되지 않은 예약은 기존처럼 숨긴다. 원래 해당 ID가 null인 예약은 유지한다. 누락된 관계가 삭제 때문인지 권한/행 수 제한 때문인지는 이 조회만으로 확정하지 않는다.
- 네 종류 조회가 모두 성공한 뒤 시간표·예약을 함께 화면에 반영한다. 실패하면 두 목록을 함께 비우고 공통 오류 핸들러를 사용한다. raw 오류·이름·전화번호를 로그/오류 문구에 쓰지 않는다. 기존 예약 상세 표시 자체는 유지한다.
- 지점·프로필·주 시작일·탭 변경 또는 화면 이탈 시 요청 번호를 무효화한다. 오래된 성공/실패는 최신 목록·오류·로딩을 변경하지 않는다. 통신을 취소하거나 DB 트랜잭션 스냅샷을 보장하는 것은 아니다.

## 검증과 남은 범위

- `npm run test:schedule`: 실제 DB·발송 없는 조회/조립/동시 조회/오류 문구 동기화 테스트.
- 페이지 순회·대량 ID 분할·실제 RLS·운영 DB 상태·브라우저 렌더는 별도 검증이 필요하다. 서버 행 수 제한 때문에 전체 예약/정원을 정확히 집계했다고 보장할 수 없다.
- `views/WeeklySchedule.tsx`: 기존 주간 그리드 JSX와 선택 상태를 담당한다. `components/ScheduleReservationDialog.tsx`가 기존 예약 명단/닫기 UI를 담당한다. 디자인 클래스와 표시 문구는 유지했다.
- `model/scheduleDisplay.ts`: 요일 별칭·브라우저 로컬 날짜·시간 범위/높이·검색·현재 선택 여부를 계산한다. 기존 시간 범위/최소 8시간 높이를 유지한다. 잘못된 DB 시간값·수업 겹침 레이아웃 정책은 이번에 변경하지 않았다.
- 부모는 검색 결과 배열을 memo로 유지하고, 프로필 ID·지점·주차·조회 요청 번호를 React key로 전달한다. 해당 범위 변경은 컴포넌트를 재생성해 이전 상세 선택을 지운다. 데이터 배열/주차/로딩이 선택 당시와 다르면 상세를 즉시 숨기며 조회 중 수업 클릭은 막는다.
- 서버 권한/RLS·대량 행·동시 조회 스냅샷·실제 브라우저 접근성/모바일/레이아웃 검수는 별도다. 이번 검증은 모의 조회와 정적 React 렌더·핸들러 호출이며 실제 운영 화면 검수로 보지 않는다.
