# 관리자 사이트 콘텐츠 경계

## 파트너 로고 업로드·저장·삭제

- `model/partners.ts`는 이름/설명·표시 순서(int32)·파일 타입/용량을 검증한다. PNG/JPEG/SVG/WebP/GIF, 0바이트 초과~10MB를 허용한다. 기존 파일을 교체하지 않으면 http(s) 로고 URL을 사용한다. 과거 base64 로고 행은 편집 시 새 이미지 업로드가 필요하다.
- `api/partnerWrites.ts`는 기존 버킷 `web_partner_logos`에 UUID 기반 `logos/<uuid>.<허용 확장자>`로 upsert false 업로드 후 public URL로 기존 테이블을 insert/update한다. 임의 파일명/경로를 사용하지 않으며 업로드 실패를 base64 DB 저장으로 우회하지 않는다.
- 파일 업로드와 DB 쓰기는 원자적이지 않다. `not_started`/`upload_unconfirmed`/`uploaded`/`row_unconfirmed`/`confirmed`와 업로드 경로·정규화 오류를 반환한다. 경로는 코드 내부 결과이며 화면/로그에 출력하지 않는다. 업로드 단계 오류에서는 DB 쓰기를 시작하지 않는다.
- 업로드 경로 응답과 public URL, DB 반환 UUID/요청 필드 일치를 확인한다. select 권한 문제나 응답 유실은 저장 실패 확정이 아니다. UI는 업로드 미확인·파일 응답 확인 후 DB 부분 결과·일반 저장/삭제 미확인을 구분하고 새 목록 확인 전 반복 실행을 막는다. 자동 재시도는 없다.
- 저장/삭제는 같은 ref 잠금과 폼/수정/삭제 버튼 잠금을 사용한다. 기존 조회 응답을 무효화하고 일반 조회가 변경과 겹쳐 재실행 제한을 풀지 않도록 한다. 변경 응답 확인 뒤 재조회 실패는 `ADMIN_PARTNER_REFRESH_FAILED`로 분리한다. 이전 화면 결과는 새 폼을 초기화하지 않는다.
- 미리보기는 blob URL을 사용하고 교체/화면 이탈 시 revoke한다. 늦은 FileReader 응답이 새 편집 폼을 덮어쓰는 경로는 제거했다.
- **파일 삭제는 하지 않는다.** DB 삭제 응답만 확인하며 기존/공유 로고 파일은 보존한다. 업로드 후 DB 실패/응답 유실에서도 파일을 제거하지 않는다. 파일이 DB에 반영됐는지 확정할 수 없기 때문이다. 미사용 파일은 남을 수 있고, 영속 복구 manifest/참조 스캔/회수 작업은 별도 설계가 필요하다.
- 조회 실패 화면의 ‘누구나 쓰기’ 허용 SQL 및 자동 복사 안내를 제거했다. 조회 오류가 테이블 부재라고 단정하거나 서버 권한 변경을 우회책으로 안내하지 않는다.
- MIME/용량 클라이언트 검사는 파일 내용 스캔·SVG 정화·버킷 정책을 대체하지 않는다. 서버 RLS·Storage 권한·public URL 정책·실제 파일 내용 검수·동시 편집·브라우저 검수는 별도다. 기존 SVG 지원은 유지했으며 업로드 보안 전체를 검증한 것은 아니다.
- `npm run test:admin-partners`: 실제 업로드/DB 연결 없이 단계별 실패·반환값·파일 보존·중복 방지·화면 수명·오류 문구 동기화를 검증한다.

## 조회

- `api/contentReads.ts`: 문의(`web_inquiries`), 영상(`web_manual_videos`), 협력브랜드(`web_partner_logos`) 목록 및 `web_settings`의 default 행을 읽는 서비스다. 기존 전체 필드 조회·정렬·단일 행 조건은 유지한다. 쓰기·결제·발송·업로드 호출은 없다.
- 목록은 정상 배열/객체 행인지 확인하며 응답 error를 검사한다. 설정은 정상 객체 또는 명시적 null만 허용하고 가격 필드의 기본 타입을 검사한다. 실패를 빈 목록이나 정상 기본값으로 바꾸지 않고 공통 오류로 정규화한다.
- 정상 조회에 설정 행/가격 값이 없을 때 기존 99000/118000 표시 기본값과 falsy/0 처리 규칙은 유지했다. 요금제 정책·허용 금액·0원 정책을 새로 정의한 것이 아니다.
- AdminPage 각 조회 진입점은 최고관리자 프로필을 검사한다. 실제 권한 보장은 서버 RLS가 담당한다. 각 자원의 요청 번호와 공통 화면 epoch로 같은 자원의 이전 응답 및 탭/프로필 변경 전 응답을 무효화한다. 이전 저장 콜백이 늦게 조회를 호출해도 현재 탭/프로필과 다르면 시작하지 않는다.
- 현재 요청 실패 시 목록을 비우고 공통 오류로 표시한다. 파트너 조회의 원시 서버 오류 로그는 제거했다. 파트너 실패 표시는 모든 원인을 DB 미연동으로 단정하지 않도록 ‘목록 조회 실패’로 바꿨다.
- 설정 조회가 끝나기 전·실패·화면 전환 이후에는 설정 저장 버튼을 비활성화한다. 이전 표시 금액을 자동 저장하지 않는다. 설정 조회 시작 시 이전 저장 성공 문구를 지운다.

## 남은 범위

- 파트너 업로드/DB 저장은 아래 단계별 서비스로 분리했다. 파일 참조를 확인하는 정리 작업·미사용 파일 회수 정책은 아직 없다.
- 숫자 정책 검증·전체 필드 최소화·대량 목록 페이지 처리·실제 RLS·로그인 갱신·브라우저 검수는 별도다. shared loading 상태도 화면 전체에서 쓰는 기존 구조를 유지한다.
- `npm run test:admin-content`: 서비스 정상/오류/비정상 응답, 화면 요청 수명, 권한 진입점, 오류 문구 동기화를 외부 연결 없이 확인한다.

## 설정 저장

- `model/settings.ts`는 양쪽 금액을 검증한다. 공란·부호·음수·소수·지수/구분자 표기·JS 안전 정수 초과를 차단한다. 기존 조회는 0원을 기본금액으로 대체하므로 0원 저장도 차단한다. 0원 운영을 지원하려면 조회/표시/계산 정책을 함께 확정해야 한다. 기존 DB 가격을 자동으로 바꾸지는 않는다.
- `api/settingsWrite.ts`는 기존 `web_settings`의 default 행에 동일 필드로 upsert를 한 번 호출한다. 반환 select/single의 오류와 id/저장 금액 일치를 확인한다. SELECT 권한이 없거나 응답이 유실되어도 저장되었을 수 있으므로 실패 확정/롤백으로 표시하지 않는다. 자동 재시도·대체 쓰기는 없다.
- 화면은 조회 준비 여부·최고관리자·현재 탭/프로필을 검사한다. 동기 ref로 연속 클릭을 차단하고 처리 중 입력/버튼을 잠근다. 성공은 응답 확인 후에만 표시하며 홈페이지 캐시/배포/다른 사용자의 최신 표시까지 보장하지 않는다.
- 저장 시작 시 이전 설정 조회를 무효화하고 저장 중 재조회를 시작하지 않는다. 탭/프로필 변경 후 이전 저장이 새 폼/성공 문구를 덮어쓰지 않는다. 저장 중 탭을 나갔다 돌아와 조회가 생략됐다면 잠금 해제 뒤 현재 설정을 다시 읽는다.
- 저장 오류/응답 미확인은 재조회 전 재저장을 막는다. 설정 탭을 나갔다 돌아오거나 페이지 새로고침으로 상태를 먼저 확인한다. 입력 검증 실패는 쓰기를 하지 않았으므로 입력을 계속 수정할 수 있다.
- 서버 RLS와 upsert 후 select 권한·동시 관리자 수정·감사 로그는 별도 검수 대상이다. 클라이언트 잠금은 다른 브라우저/기기의 쓰기 충돌을 막지 않으며 서버 버전 비교/트랜잭션은 추가하지 않았다.
- `npm run test:admin-settings`: 실제 DB 변경 없는 입력·반환값·권한/서버 오류·응답 유실·중복 클릭·화면 전환 테스트와 오류 문구 동기화를 확인한다.

## 영상 매뉴얼 저장·삭제

- `model/videos.ts`가 기존 ID 추출·단계 번호 제거·자동 duration·카테고리 라벨·접근 표시 필드를 준비한다. 제목/URL 필수 및 제목 150자, 카테고리/수정·삭제 UUID를 검사한다. 신규 display_order 0, 수정 시 기존 순서 유지, 저장 시 is_visible true 규칙은 기존 그대로다.
- 기존 URL 추출 정규식의 동작을 유지했다. 앞뒤 공백이 있는 URL의 ID 추출 실패나 비유튜브 URL의 null ID도 기존대로다. 실제 동영상 길이 조회/호스트 허용목록/URL 보안 검증은 추가하지 않았다. 제한 필드는 서버 접근 제어를 대체하지 않는다.
- `api/videoWrites.ts`는 기존 insert/update/delete를 한 번 호출한다. 저장은 반환 UUID·요청 필드 전체(단계 배열 포함), 삭제는 반환 UUID를 확인한다. 오류/응답 유실/행 누락/불일치에서 자동 재시도나 다른 테이블 쓰기로 우회하지 않는다. select 권한 오류라도 앞선 변경이 적용됐을 가능성이 있다.
- 화면은 관리자·현재 탭/프로필·정상 목록 조회를 확인한다. 저장과 삭제는 같은 ref 잠금을 사용하고 처리 중 폼과 수정/삭제 버튼을 잠근다. 취소 확인·입력 검증 실패는 쓰기를 하지 않는다.
- 저장/삭제 오류·미확인 결과에서는 폼/목록을 성공 상태로 미리 바꾸지 않고 재실행을 막는다. 영상 탭을 다시 열거나 새로고침해 정상 목록을 확인한 뒤 판단한다. 저장 중 일반 조회는 시작하지 않고, 변경 응답 확인 후의 명시적 재조회만 허용한다.
- 서버 변경 응답 확인 뒤 목록 조회가 실패하면 `ADMIN_VIDEO_REFRESH_FAILED`로 별도 안내한다. 이전 화면의 응답이 새 폼을 초기화하지 않는다. 저장 중 화면을 바꾼 뒤 돌아온 경우 잠금 해제 후 현재 탭 조회를 다시 요청한다.
- 실제 RLS/수정·삭제 및 반환 select 권한·동시 편집·공개/제한 영상의 서버 노출 정책은 별도다. 로컬 과거 스키마에는 anon 관련 부여가 있으나 현재 운영 정책을 확인/변경한 것은 아니다. 이 프론트 분리로 서버 보안까지 보장하지 않는다.
- `npm run test:admin-videos`: 실제 DB/유튜브 연결 없이 응답 확인·입력·중복 실행·새 화면 보호·부분 결과·문구 동기화를 검증한다.
