# 대시보드 조회 경계

- `api/dashboardReads.ts`의 `loadDashboardSnapshot`은 기존 학생·활성 수업·월별 예약/출결/청구·문자 포인트 잔액·본사 공지를 읽는다. 기존 필드·기간·정렬·지점 필터를 유지하고, 7개 응답이 모두 정상 배열일 때만 결과를 반환한다. 트랜잭션 스냅샷/전체 행 조회 보장은 아니다.
- 학생의 자녀/부모 삭제 필터는 조인 object/array를 정규화한 뒤 적용한다. 연결 데이터 자체가 없는 행의 기존 표시 규칙은 유지한다. 본사 공지 실패/0건에 예시 공지를 넣는 대체 경로는 제거했다.
- 화면은 관리자 포털 역할과 지점 범위를 확인한다. 일반 계정은 필터보다 자기 지점이 우선이며 지점이 없으면 전체 조회로 넓히지 않는다. 실제 접근 제어는 서버 RLS가 필요하다.
- loader는 useCallback이며 현재 지점/계정 및 요청 번호가 일치할 때만 일괄 반영한다. 실패하면 이전 통계를 비우고 공통 오류로 안내한다. 오래된 응답/오류는 새 데이터·로딩을 변경하지 않는다.
- 통계 산식·화면 디자인·기존 UTC 기준 초기 날짜/월 및 로컬 연도·자정 자동 갱신 미지원은 유지했다. 한국시간 경계 통일/다중 시간대/날짜 자동 갱신은 별도 검토다. DB의 금액/포인트 타입·행 수 제한·예약 취소 상태와 회계적 집계 정책도 이번에 재정의하지 않았다.

## 예전 관리자 모달

- `components/AdminDashboardModal.tsx`는 현재 정적 코드 검색상 외부 호출처가 없는 예전 통합 관리자 창이다. 실제 대시보드 KPI 상세 대상 모달로 보지 않으며 이번에 삭제/연결하지 않았다.
- 선택적인 profile prop을 추가했으며 관리자 프로필 없이는 표시/조회하지 않는다. 향후 사용 시 확인된 관리자 프로필을 명시적으로 전달해야 한다. UI 검사만으로 서버 권한을 보장하지 않는다.
- `loadLegacyDashboardTab`은 기존 문의·영상 목록과 default 설정을 읽는다. 기존 미구현 결제/출결 탭은 새 DB 조회를 추가하지 않는다. 닫힘·탭·계정 변경/화면 이탈 후 이전 응답/오류를 막고 설정 조회 전/실패 시 저장 버튼을 비활성화한다.
- **모달 저장/문의 상태 수정/영상 추가 경로는 여전히 예전 코드**다. 실제로 다시 연결하기 전 공통 오류·권한·응답 확인·중복 실행·화면 전환을 별도 점검해야 한다. 현재 사용 중인 AdminPage의 개선된 저장 서비스와 동일한 안전성을 가졌다고 보지 않는다.

## 검증

- `npm run test:dashboard`: 실제 DB·결제·발송 없이 7개 조회 오류/형식·기간/지점·학생 조인·계정 전환·모달 수명을 확인한다. 실제 RLS·브라우저·대규모 데이터·서버 집계 검수는 별도다.
