# 출결 영역 분리 현황

## 현재 경계

| 파일 | 역할 |
| --- | --- |
| `api/attendanceLedger.ts` | 월별 장부의 자녀·이용권·과거 출결·탈퇴·보호자·사용 기록 조회 |
| `api/dailyAttendance.ts` | 실시간 화면의 학생·활성 수업·당일 출결·예약 전체 조회 |
| `api/calendarAttendance.ts` | 월간 달력의 출결·취소되지 않은 예약 조회 |
| `api/ledgerActions.ts` | 월별 장부의 수동 출석 등록·취소 RPC와 응답 확인 |
| `api/timelineAction.ts` | 단일 실시간 타임라인 상태 변경의 기존 순차 저장 |
| `api/timelineNotification.ts` | 저장 후 출결 알림 요청. 단일/일괄 경로에서 공유 |
| `model/timelineActions.ts` | 단일/일괄 동작·확인 상태 타입과 알림 대상 동작 |
| `model/attendanceLedger.ts` | 조회 결과를 날짜/횟수/원본 기록 ID를 가진 장부 행으로 변환 |
| `model/dailyAttendance.ts` | 실시간 학생 표시·시간·승하차/결석 기록 병합 |
| `model/ledgerRules.ts` | 기존 월 범위·한국 날짜·횟수·표시 제외·30회 슬롯 규칙 |
| `types.ts` | 장부 행/취소 원본 식별자와 읽기 결과 타입 |
| `../AdminPage.tsx` | 현재 출결 UI/state·쓰기·각 조회 요청 수명 |

## 유지한 규칙

- 기존 공통 페이지 조회와 ID 묶음 조회를 그대로 사용한다. 하나라도 조회 실패 시 부분 장부를 반환하지 않는다.
- 선택 지점 필터와 차량권 제외 조건을 유지한다. 최고관리자만 전체 지점 조회를 허용하는 기존 화면 범위를 사용하며, 일반 관리자의 지점이 없으면 조회 전에 차단한다. 실제 접근 권한은 서버 RLS로 별도 검증해야 한다.
- 예약 연결 사용은 예약일, 직접 차감은 한국시간 날짜로 해당 월을 판단한다. 결석·보강·삭제 예약은 기존처럼 제외한다. 사용 수량만큼 날짜를 표시하고 직접 기록의 ID/시각을 취소 근거로 유지한다.
- 실제 사용 기록이 없고 이용권이 한 개인 경우에만 과거 `attendance_logs`를 보완한다. 여러 이용권에 같은 과거 기록을 복제하지 않는다.
- 삭제 자녀/부모와 환불 완료·환불 없음 탈퇴자는 제외한다. 환불 대기는 유지하고 자녀별 탈퇴 정보를 계정별 정보보다 우선한다.
- 이용권 없는 자녀도 0회 행을 유지한다. 표시 슬롯·전체/사용 횟수는 기존 30회 상한을 유지하며 잔여 횟수의 계산 정책은 바꾸지 않았다.
- 정렬·기본 표시명·과거 기록의 취소 원본 없음(null)도 유지했다. 오래된 요청의 응답은 최신 state를 덮어쓰지 않는다.

## 실시간·월간 달력 조회

- 기존 학생/출결/예약 필드와 날짜·지점·보관/삭제 필터를 유지한다. 예약의 취소 상태 5종은 공통 규칙으로 제외한다. 앱 연결 학생은 기존 활성 수업 조회 함수를 사용한다.
- 실시간 조회는 학생·수업·출결·예약 모두 성공한 뒤 다섯 상태를 함께 반영한다. 오류가 있으면 해당 상태를 모두 비우고 공통 안내를 표시한다. 달력도 출결·예약 둘 중 하나가 실패하면 모두 비운다.
- 일별/달력 요청 번호는 별도다. 지점·기간·탭 변경/화면 이탈 후 이전 성공·실패가 새 상태를 변경하거나 예전 오류를 띄우지 않는다.
- 최고관리자가 아닌 계정에 지점이 없으면 전체 지점 조회로 이어지지 않는다. 실제 권한 보장은 서버 RLS와 별도 검수가 필요하다.
- 기존 시간 변환 함수는 이름과 달리 브라우저 로컬 시간을 사용한다. HH:mm 문자열은 그대로 사용한다. 승하차 상태만 있고 시각이 없으면 기존 14:00/16:00 보완값을 유지한다. 정확한 이벤트 시각을 새로 검증/수집한 것은 아니다.
- 일별/달력 조회의 대량 행 페이지 처리와 과거 선택일 기준 활성 수업 판정은 이번에 변경하지 않았다. 공통 수업 함수는 기존처럼 현재 날짜를 사용하므로 과거 이력 해석은 별도 검토해야 한다.

## 수동 출석 등록·취소

- 기존 `register_manual_ledger_attendance`와 `cancel_attendance_ledger_entry`만 호출한다. 유효한 자녀·이용권 UUID와 날짜를 검사하며 예약 선택·권한·차감/복구·서버 잠금 규칙은 기존 RPC가 최종 판단한다.
- 등록의 `registered`/`already_registered`, 취소의 `cancelled: true`와 0 이상의 정수 `restored`를 확인한다. 응답 유실/형식 미확인은 출석·차감/복구 실패 확정이 아니다. 자동 재시도나 직접 테이블 수정 우회는 없다.
- 취소의 원본 사용 ID와 소비 시각은 변경하지 않고 전달한다. 과거 기록은 기존 null 원본 계약을 유지한다. 서버 응답에 식별자가 없으므로 동일 행을 반환 ID로 대조한 것으로 안내하지 않는다.
- 등록·취소는 서로의 동기 잠금을 검사한다. 처리 중 장부의 쓰기 버튼과 새 등록창 열기를 차단하며 finally에서 상태를 해제한다.
- 처리 확인 뒤의 재조회 실패는 `ATT_LEDGER_REFRESH_FAILED`로 별도 안내한다. 지점·월·탭 전환 후 이전 요청은 새 장부를 재조회하거나 새 등록창을 닫지 않는다.
- 실제 다중 기기 중복 처리·서버 RPC 배포·원본 시각 충돌·RLS·이용권 복구는 격리 검수가 필요하다. 클라이언트 잠금은 다른 기기의 동시 실행을 막지 않는다.

## 단일 실시간 타임라인

- 승하차·등하원·미탑승·결석·각 상태 취소·전체 초기화의 기존 테이블/RPC 호출 순서를 유지했다. 단일 처리는 미리 성공 상태를 표시하지 않고 저장 응답 후 해당 날짜를 재조회한다.
- 없는 학생이나 불명확한 지점에는 쓰기를 시작하지 않는다. 단일 경로의 `branch_1` 기본값은 제거했다. 실제 학생/예약/이용권 접근 권한은 서버가 최종 보장해야 한다.
- 모든 Supabase 응답 오류를 검사한다. 미탑승의 셔틀 기록 저장 오류도 더 이상 무시하지 않고 후속 단계를 중단한다. 반환하는 `completedSteps`는 오류 없는 응답 단계 수이며, 파일/사용자 단위 트랜잭션이나 실제 영향 행 수가 아니다.
- 일부 응답 후 실패 또는 응답 유실은 출결·예약·이용권 중 일부 변경 가능성을 안내한다. 자동 재시도·자동 롤백·RPC 실패 후 테이블 우회는 없다. 오류 시 최신 기록을 조회해야 한다.
- 알림은 저장 경로가 오류 없이 끝난 경우만 요청한다. 실패는 `ATT_NOTIFICATION_FAILED`로 분리하며 일괄 경로도 공통 알림 서비스를 사용한다. `stored`/`pushed`/`skipped`는 서버 응답 참고값이지 기기 수신 보장이 아니다. 알림 실패 전 알림함 저장이 되었을 수도 있다.
- 확인 실행은 동기 ref 잠금으로 연속 클릭을 막고 장부 쓰기와도 충돌을 차단한다. 지점/날짜/탭이 바뀌면 이전 단일 처리가 새 목록을 재조회하거나 새 확인창을 닫지 않는다.
- **아직 남은 서버 계약**: 여러 쓰기는 원자적이지 않으며 일부 update/delete는 반환 행 수를 확인하지 않는다. `process_lesson_check_in`의 오류 검사만 기존대로 유지했으며 `no_reservation`/`no_available_package` 같은 비오류 상태에 대한 업무 정책 검증을 새로 정의하지 않았다.
- 실시간 초기화/등원 취소는 기존 상태 필드 변경 경로다. 장부 취소 RPC처럼 사용 횟수 복구를 보장하는 기능으로 안내하면 안 된다. 서버 트랜잭션/취소·복구 계약은 별도 검토가 필요하다.
## 일괄 실시간 타임라인

- `api/batchTimelineAction.ts`가 기존 단일 저장 서비스를 학생별 순차 호출한다. 확인창을 열 때 중복을 제거한 대상 ID를 고정하며, 실행 직전 모든 학생·일정·지점을 검사한다. 불명확한 지점을 `branch_1`로 대체하지 않는다.
- 저장 전 성공 상태를 화면에 반영하지 않는다. 학생별 `responses_received`(모든 저장 응답에 오류 없음), `review_required`(일부 단계 처리/응답 미확인), `not_attempted`(미실행)를 구분한다. 첫 저장 문제 이후 남은 학생은 실행하지 않으며 자동 재시도·롤백을 하지 않는다.
- 저장 경로가 오류 없이 끝난 학생에게만 선택한 알림을 요청한다. 뒤 학생의 저장 실패가 있어도 앞 학생의 알림 결과는 별도 기록한다. 알림 실패는 저장 실패로 취급하지 않는다. 화면의 요약은 인원만 표시하며 개인정보를 넣지 않는다.
- 지점·날짜·탭 변경 시 이미 시작된 학생 저장을 되돌릴 수는 없지만 이후 학생 쓰기·알림 요청을 중단한다. 이전 결과로 새 화면의 목록/확인창을 변경하지 않는다. 같은 화면이면 최종 재조회한다.
- `responses_received`는 실제 영향 행 수·이용권 차감·알림 수신 보장이 아니다. 단일 경로와 동일하게 서버 트랜잭션, RPC 비오류 업무 상태, 다중 기기 충돌, 취소·복구 정책은 별도 검증이 필요하다.

## 검증과 남은 작업

- `npm run test:attendance`: DB 연결 없는 실사용 경로 회귀·순수 계산·조회 실패·화면 요청 수명 테스트.
- 장부 등록/취소·단일/일괄 타임라인 요청·공통 알림은 분리했지만 서버 RPC·SQL·큰 JSX는 변경하지 않았다.
- 모의 데이터 검증은 실제 앱·키패드·웹 동시 처리, 실제 RLS/대규모 DB 조회/브라우저 검수를 대체하지 않는다. 서버 계약 검토와 실제 브라우저 검수는 남아 있다.
